# D1Env 验收矩阵

每项记录 `PASS / FAIL / NOT_RUN`、命令、退出码、环境、日志位置与日期。NOT_RUN 不能折算为 PASS；单元模拟、真实 Docker、回放数据和真机证据分列。

| ID | 阶段 | 场景 | 通过条件 |
|---|---|---|---|
| A01 | M0 | 上游来源未锁定 | 有真实 SHA 或明确 blocked；不能伪造 hash |
| A02 | M1 | 未知型号/固件/缺失工件 | 返回可解释阻塞项，真实执行不可用 |
| A03 | M1 | 无 GPU 的 CPU 部署 | 不因 GPU 缺失而误阻塞 |
| A04 | M1 | Docker 不存在/无权限/超时 | 分别报告，不升级权限“修复” |
| A05 | M1 | 字段注入/执行型 YAML/路径异常 | 输入被拒绝，不产生任意命令执行 |
| A06 | M1 | 重复请求/两个运行进程 | 单目标最多一个变更作业，计划 ID 稳定 |
| A07 | M1 | 服务中断后重启 | INTERRUPTED＋资源盘点，不假报成功 |
| A08 | M1 | 取消/回滚 | 不删除其他项目或用户地图/bag |
| A09 | M2 | localhost 非法来源/无会话/CSRF | 不能读取敏感结果或启动作业 |
| A10 | M2 | 缺失遥测/旧数据 | UNKNOWN/null 或 stale，不显示正常 |
| A11 | M2 | 演示流程与截图 | 所有视图/报告显著 MOCK，不冒充 Docker/实机 |
| A12 | M2 | 刷新、失败、导出 | 作业可恢复显示；错误含证据；报告去敏 |
| A13 | M3 | 真实 Docker 生命周期 | 真正创建/运行/验证/停止本项目容器 |
| A14 | M3 | 容器活着但业务不正常 | readiness 失败，不能只看 running |
| A15 | M3 | 下载中断/摘要不符/离线导入 | 可解释恢复；拒绝不符工件/路径逃逸 |
| A16 | M3 | 全新 Ubuntu VM 安装 | 不依赖开发工具；实际桌面入口可用 |
| A17 | M3 | 已有系统与 Docker | 不覆盖原设置；重复安装不破坏已有资源 |
| A18 | M4 | 一个精确组合的只读 SDK | 有实际遥测/新鲜度/错误恢复，未发送运动 |
| A19 | M4 | 机器人侧配置写入 | 默认不写；任何写入有明确现场授权与恢复方法 |
| A20 | M5 | TF/时间戳/传感器协议 | 唯一发布、正确时钟、测量外参、数据来源可信 |
| A21 | M5 | 地图/定位/规划 | 真数据或标识清楚的回放；命令仅入记录端 |
| A22 | M6 | 控制权限/过期命令/故障 | 硬件证据支持具体行为，重启不自动重武装 |
| A23 | M6 | 整台主机失联 | 现场测试本体侧失联机制；否则禁止运动 |
| A24 | M6 | 物理停止与模式差异 | 人工验证；软件 Stop 不冒充硬件急停 |

## 发布声明模板

可接受：“Ubuntu 22.04 x86_64 上真实 Docker 探针部署验证通过；D1 实机尚未验证。”

可接受：“在记录的固件和 SDK 下，指定轮足配置的遥测已验证，运动功能仍禁用。”

不可接受：“所有 D1 一键即用”，若只有菜单、模拟数据或单个型号测试。

不可接受：“断网自动安全停机”，若只有上位机 watchdog 单元测试。

## 每阶段最小报告

报告包括目标/实际完成范围、环境与来源版本、运行命令和退出码、通过/失败/跳过数、真实截图来源、失败操作及修复证据、未验证内容、阻塞项和下一阶段入口。

人工制造测试故障可以用于测试，但必须写明“故障注入测试”，不能编造为真实用户遇到的问题。截图必须来自实际运行的软件，不能用绘图或生成图片作为测试证据。

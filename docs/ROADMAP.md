# 从演示产品到真实一键部署

本文件规定后续阶段的输入、出口和停止条件，不授权自动执行真机操作。M0–M2 详见基础实施计划。后续每阶段应先根据上一阶段真实结果写独立的小计划，不同时实现所有子系统。

后续阶段遵循用户确认的 [IOENV 分层蓝图](IOENV_BLUEPRINT.md)：环境定义、容器管理与机器人业务启动分开；参考上游配置与生命周期机制，独立实现部署引擎。每轮计划要写清上游参考路径、D1Env 承接模块、保留/改造行为和验收证据。成品目标是 UI 部署已适配环境、启动指定功能并可信检查；M3 的容器/ROS 探针只验证其中的软件基础链。

## M3：真实 Docker 与安装体验

输入：M2 核心契约与安全测试通过。输出：实际 DockerExecutor、CPU ROS 探针配置、可重复运行的 Compose 方案、真实构建安装包与发行元数据。

任务边界：只对本项目创建的容器/网络做操作，不连接机器人。探针容器之间真实发布/订阅 ROS 消息；它证明软件通信，不证明 D1 驱动。

| 子任务 | 必须交付的证据 |
|---|---|
| DockerExecutor | 白名单操作、argv 而非 shell、真实退出码、超时、取消、归属标签 |
| 镜像构建 | Dockerfile、真实源码/包版本锁、构建日志、许可证清点、真实 image ID/digest |
| Compose | 配置静态检查和真实运行；默认非 privileged，不映射整个 /dev |
| 健康检查 | 两个实际进程/容器完成带时间戳消息的 pub/sub，而非只检查 running |
| 恢复 | daemon 不可用、下载失败、端口冲突、中断和重复执行测试 |
| 发行包 | 干净 Ubuntu VM 中安装并从桌面打开；用户不需开发工具 |
| 离线导入 | 可信校验值、归档路径/容量限制、不能关闭 TLS 或执行任意包内脚本 |

安装包尚未构建前，不能宣称“下载安装即用”。发布镜像/发行包是外部写操作，需用户选定仓库并授权；否则先做本地工件，不制造不存在的 registry URL。

验收出口：一次全新环境安装、一次重复安装、一次失败恢复，有实际日志/截图和精确环境信息。此时可宣称“软件部署链验证通过，未接真机”。

## M4：单个准确组合的 SDK 只读接入

输入：机器人现场资料和操作人员授权；厂商仓库的实际 SDK/固件/CPU 信息。由界面配置选择目标，但驱动适配按组合逐一实现。

优先从 Edu-Ultra 的高层 C++ SDK 候选开始；若现场型号是 MaxPro 则改为对应分支，不强行要求更换机器人。MaxPro 高层不默认引入 ROS1。先静态检查动态库依赖，再做准确目标架构上的构建；不能用 QEMU 编译通过当成真实时序验证。

只读适配职责：连接与状态、厂商支持的遥测读取、类型/单位转换、连接新鲜度、结构化错误；不暴露运动调用。SDK 初始化行为也要验证，不能仅凭类名认定零副作用。

SDK ABI 与当前 ROS 运行时冲突时才考虑独立旧运行时容器，通过小型、严格类型的本地 IPC 提供遥测；不要先搭完整 ROS1 bridge。该隔离方案需要另写接口及测试计划。

本体网络配置第一步仅查看、生成差异与恢复说明；修改启动脚本/目标地址、重启本体均需现场确认和独立写操作授权。禁止默认复用厂商文档里的通用密码。

验收出口：实际遥测采集、时间戳/频率、掉线与恢复记录；仅标注测试过的准确硬件/固件/SDK/CPU/网络组合为 telemetry hardware_verified。

## M5：传感器、建图、导航软件链

先绑定实际传感器与话题，不向用户展示一堆未接通算法的“任选菜单”。必须核实点云格式、IMU、时间同步、外参、里程计的可用性和坐标系。

最小目标为室内平地 2D：有效扫描与里程计 → SLAM Toolbox 或已验证定位来源 → Nav2 → 命令只读记录端。没有合格里程计时先解决里程计，不发布假的 /odom 让界面变绿。

通过检查：TF 每条边唯一、消息新鲜、仿真/真机时钟分开、地图保存/加载不丢失、生命周期正确、导航目标能取消、命令可记录。此阶段仍禁止导航直接输出到机器人。

FAST-LIO、LIO-SAM、3D 导航和 RL 训练分开扩展，不能只改配置名就标记可用。点足/轮足不同姿态的 footprint、非完整运动约束及速度范围必须分别验证。

## M6：运动安全设计与现场验收

这是独立安全敏感阶段，需要现场人员、厂家操作手册、可用的物理停止途径和明确运动授权。Codex 可以实现并测试软件网关，但不能替代物理验收。

软件网关要有单一控制权、命令有效期、限幅/变化率限制、状态许可、过期遥测阻断、重启撤销授权。当前上游没有证据的 e-stop/heartbeat 方法不允许猜一个函数实现。

特别测试：关闭浏览器、停止导航进程、杀死网关、上位机断电、拔掉通信链路、遥控器抢占、命令源切换及姿态模式切换。主机完全失联时，只有本体侧机制还能作用；不能靠上位机定时发送 0 保证这个场景。

如果本体断连行为或停止权限没有验证，运动功能保持禁用。`move(0,0,0)`、passive、趴下和物理急停的区别必须由实际文档与现场证据决定。

验收出口：只对完整已测试组合发布 hardware_verified 记录；包含操作者、日期、固件、SDK、工件摘要、测试方法与结果。一次通过不推及其他 D1 型号。

# 直接交给 Codex 的分轮提示词

这些指令需在本研发包所在的项目目录执行。先阅读设计，采用方案后再发送相应轮次；不要一次发送全部轮次。复制某轮次即授权该轮次列出的软件工作，不授权未列明的现场写入/运动。

## 第一轮：来源审计＋部署核心＋中文演示向导

```text
我选择采用本目录的 D1Env 设计，并让你按阶段实施。请先阅读：
1. AGENTS.md
2. docs/research/SOURCE_AUDIT.md 与 SOURCES.md
3. docs/superpowers/specs/2026-10-06-d1env-design.md
4. docs/superpowers/plans/2026-10-06-d1env-foundation.md
5. docs/ACCEPTANCE.md

只执行基础计划的 Task 0–7（M0–M2），不要进入 M3–M6。

先检查当前工作区和上游实际代码。简要列出你核到的架构、来源差异与本轮任务，然后开始实现，不要停在泛泛建议。无法取得的来源/版本明确 blocked，不造 commit SHA；可继续独立的 MOCK/UI 工作。

用 TDD，逐任务实现和验证。交付严格 Profile、只读 Doctor、确定性计划、持久化作业、CLI/API、中文五步向导、MOCK 演示、故障页和去敏报告。真实型号尚未支持时必须明确禁用；UNKNOWN 不能显示成正常。

本轮不连接机器人、不运行厂商 SDK、不创建真实 Docker 容器、不改网卡/驱动/固件、不实现 arm 或运动 API。不要一口气实现导航和远程安装。

截图必须来自实际运行界面，MOCK 标识不能隐藏。每阶段报告实际测试命令、退出码、通过/失败/跳过及未验证范围。不要把模拟日志写成真机日志。

完成后给出项目启动方法、实际截图和 reports/M2-summary.md，做一次针对误报成功/注入/权限/重复作业的审查。停止在 M2。
```

## 第二轮：真实 Docker 与可安装软件

前提：看过第一轮报告与界面，接受其结果；开发机具备允许创建测试容器的环境。

```text
现在只实施 docs/ROADMAP.md 的 M3。先读取上一轮真实报告并检查代码，再将 M3 分解为明确任务和测试，然后实现。

加入真正的 DockerExecutor、CPU ROS pub/sub 探针、可追溯的 Dockerfile/依赖锁、生命周期与健康检查、取消/恢复、工件校验和 Ubuntu 安装包。只操作本项目拥有的测试资源。

我要真实软件执行，不接受 mocked Docker 输出冒充成功。没有 Docker/下载权限/CI 时明确报告受阻，不能补造测试记录。镜像 ID 与 registry manifest digest 分开记录；未发布就使用本地真实工件，不编造下载地址。

终端用户安装后无需 npm/pip/Git 或手工编译。验证干净 Ubuntu 环境与已有 Docker 环境，保留原设置。安装管理员步骤须可审查。

不连接机器人，不修改本体，不做运动。未经我指定仓库和授权，不推送代码、发布镜像或公开发行包。
```

## 第三轮：准确型号的只读 SDK 候选

前提：已具备现场信息；此提示词仍不授权运动。

```text
现在只做 M4 的只读适配。先读取 docs/ROBOT_INTEGRATION_CHECKLIST.md 与已提供的现场数据，不能猜型号、固件、CPU、传感器或 SDK 方法。

按所选 SDK 家族编译独立的高层只读适配器。先确认初始化行为、ABI、返回码、单位、坐标系和时间戳；不要运行厂商整套 demo 当健康检查。MaxPro 高层不默认引入 ROS1。

先完成软件测试和准确环境构建。任何访问真实设备、修改机器人配置或重启本体，分别列出具体操作并取得现场授权。没有授权只生成候选、差异和检查报告。

不要实现运动调用，不覆盖厂商脚本、不默认使用通用密码、不声称所有型号兼容。对每个准确组合记录实际证据与未验证项。
```

## 第四轮：传感器与导航只读链

```text
只按 M5 实现已经明确型号/格式的传感器、里程计、TF、建图和 Nav2 链。先核对真实数据和时间同步，缺数据就阻塞相应能力，不发布假 /odom 或假 TF。

目标是室内平地 2D；不开发台阶/跳跃/形态切换。导航输出只进入命令记录端，不能发送到真机。

记录实际地图保存/加载、定位、规划、取消、过期数据与 TF 冲突测试。演示、回放、真数据必须区分。完成后仍保留运动禁用。
```

## 独立审查提示词

```text
请把这个项目当成准备交给实验室新手的软件来审查，而不是给好评。

先实际读取代码和 reports，不只看 README/截图。重点检查：模拟是否冒充真实、容器启动是否冒充 ready、未知型号是否可以绕过、命令/路径注入、localhost 认证与 CSRF、Docker 权限边界、重复任务、进程中断恢复、误删地图/卷、错误时间戳/TF，以及运动接口是否越过当前阶段。

优先输出能定位的阻塞项，注明文件、触发条件和最小重现；之后给需要补的测试。没有实际运行的部分标为未验证。不要把自动审查写成人工或现场安全认证。
```

## M6 不提供无条件“自动真机执行”提示词

到该阶段必须基于现场安全条件、厂商停止机制和具体授权单独制定试验步骤。软件代理可继续编写测试，但不能凭本研发包自行移动机器人。

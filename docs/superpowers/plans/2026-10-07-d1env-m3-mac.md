# D1Env M3 Mac 开发与真实软件部署实施计划

> **For agentic workers:** 使用 superpowers:executing-plans / test-driven-development 按任务实施；独立模块并行，集成顺序执行，完成后独立审查。本轮用户已明确要求执行 Mac 上可开发的成品部分。

**Goal:** 把 M2 演示核心推进为可从中文 UI 实际部署、检查、停止 CPU ROS 软件测试服务的工具，并实现发行资源、离线导入与安装包基础；保留 Linux 桌面与硬件未验证边界。

**Architecture:** 继续 IOENV 的环境定义、容器管理、独立业务启动分层。严格 Profile 解析可信工件；CLI/UI 共用持久任务服务，通过受限 DockerExecutor 启动两个带时间戳消息的 ROS 进程并验证新鲜度。真实软件测试模式与 MOCK、机器人只读分开。

**Tech Stack:** 现有锁定 Python/FastAPI/Pydantic/SQLite/Typer 与 React/TypeScript/Vite；Docker Engine/Compose v2、ROS Humble；镜像依赖以实际构建记录锁定。

**Spec:** `docs/superpowers/specs/2026-10-06-d1env-design.md`、`docs/IOENV_BLUEPRINT.md`、`docs/ROADMAP.md` M3；A13–A17。

## Global Constraints

- 不连接机器人、运行厂商 SDK、改网卡/驱动/固件或实现 arm/运动接口。
- 默认 MOCK；新增 `software_test` 只部署 CPU ROS 通信探针，`verified_scope=software`，不提升任何 D1 支持等级。
- 真实操作只使用本项目本次拥有的资源；不删除用户镜像、地图、bag 或其他项目。
- 参数为严格数据、argv；禁用自由 shell/Compose 输入、默认 privileged、host 网络、整个 /dev、root SSH、xhost+。
- Web 仅回环、会话/Host/Origin/CSRF 均保留。Docker 权限是高权限信任边界。
- 工件来自真实来源，记录不可变 ID/digest、架构、版本与许可；未知信息 blocked，不捏造。
- Mac Docker Desktop 的 Linux aarch64 测试与原生 Ubuntu 22.04 x86_64 / 干净 VM 桌面验收分别记录。
- 不自动推送 GitHub或发布镜像；本轮本地工件与小提交。安装包不能要求终端用户手装 Node、编译 ROS 或编辑 YAML。

## Review Focus

1. 浏览器伪造镜像/命令/挂载：只能选择随包 Profile，执行器再次验证固定操作与工件（Task 1/2）。
2. 外部资源同名、任务中断、取消竞态：标签和资源身份核验，盘点与归属清理，不越权删除（Task 2/4）。
3. 容器 running 但无消息、消息过期/未来/错误来源：软件检查失败，不显示成功（Task 2/3/5）。
4. 历史 SUCCEEDED 和重复请求：复核实际资源与健康；重复不创建第二套容器，停止后可显式新任务（Task 4）。
5. 离线归档/发行资源路径逃逸、替换工件和依赖缺失：拒绝异常输入，安装目录与可写状态分离（Task 6）。
